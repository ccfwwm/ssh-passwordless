# 免密配置是怎么发生的

这份文档解释脚本内部的阶段划分、安全模型和密码的生命周期。给用户解释「为什么这样更安全」时可以直接引用。

## 一次配置的五个阶段

| 阶段 | 动作 | 落盘/落远端的东西 |
|---|---|---|
| 1 keygen | 生成或复用一把 Ed25519 密钥（`~/.ssh/sshpl_<target_id>`） | 私钥权限收紧到当前用户 + LocalSystem |
| 2 connect | 用窗口里输入的密码登录，同时校验主机指纹 | 首次信任时把主机公钥追加进 `known_hosts` |
| 3 install | 通过 SFTP 把公钥追加到远端 `~/.ssh/authorized_keys` | 先加远端锁 → 写临时文件 → `posix-rename` 原子替换 |
| 4 config | 写 `~/.ssh/config.sshpl_<target_id>`，并在 `~/.ssh/config` 里维护一段托管 `Include` | 只增不改，托管块外的内容一个字节都不动 |
| 5 verify | 用隔离配置（`-F` 指空文件、禁用 agent、禁用密码认证）直连复核 | 不写任何东西 |

`target_id` = `别名-<用户名@主机:端口 的 sha256 前 16 位>`，保证同一目标多次运行得到同一把密钥、同一个配置文件，不会越配越多。

## 密码的生命周期

1. 用户在窗口里输入，值只存在于该窗口进程的内存中。
2. 窗口把 `{host, port, user, password}` 作为**一行 JSON** 写到标准输出；父进程只在设置了内部管道标记（`SSH_PASSWORDLESS_CHANNEL`）时才读取它。
3. 父进程读完立刻交给 paramiko 的密码认证，安装完公钥后把变量置空。
4. 全程不写盘、不进命令行参数、不进环境变量、不进日志。错误信息统一过 `redact_sensitive()`，即使服务器回显了密码也会被替换成 `[REDACTED]`。
5. 终端模式（`--terminal`）走 `getpass`，同样不回显、不落盘。

## 主机指纹策略

- `known_hosts` 已有该端点的记录：**必须完全一致**，不一致立即中止（可能重装或中间人）。
- 记录被标 `@revoked`：无条件中止。
- 端点没有任何记录：窗口里点「测试连接」后，会先在传输层读取服务器公钥并显示 `SHA256:` 指纹，要求用户勾选「我已通过可信渠道核对」；勾选后该指纹会作为本次安装的固定指纹传给核心逻辑，**整个安装过程只接受这一把主机密钥**，并通过后才写入 `known_hosts`。

也就是说：首次信任仍然是「用户确认过一次」，而不是静默接受。命令行下用 `--expected-host-key-sha256` 达到同样效果。

## 远端写入为什么不会破坏别人的 key

1. 用 `id -u` 确认远端用户，`~` 必须规范化为绝对路径。
2. `~/.ssh` 与 `authorized_keys` 逐项校验：不能是符号链接、属主必须是本人、权限必须 700 / 600。
3. 抢锁：远端 `mkdir` 一个锁目录并写入 pid，读取端确认 pid 与持有者一致；锁持有者进程死亡后才会被清理。
4. 合并：按「算法 + 公钥体」比较，已存在就原样返回（幂等）；追加时保留原有字节与换行风格。
5. 写临时文件（0600，独占创建）→ 校验元数据 → `posix-rename` 原子替换；替换后再校验一次元数据，异常则用备份回滚。

## 撤销与回滚

- 本地：删 `~/.ssh/sshpl_<target_id>`、`.pub`、`~/.ssh/config.sshpl_<target_id>`；`~/.ssh/config` 里的托管 `Include` 可以留着（它只是挂载目录内的文件）。
- 远端：从 `authorized_keys` 删掉注释为 `ssh-passwordless:<target_id>` 的那一行。
- 如果只是想换密钥：先按上面删本地文件，再重新 `setup`，旧的远端条目保留也不会造成风险。
